# The [flask] extra is just `flask>=2.0`, already present via Dash's bundled
# backend. 2.3.3 is the floor because this site depends on three things that
# landed between 2.0 and 2.3.3: merge semantics for register_page_metadata
# (2.2.0 — without it the root re-registration below silently blanks the home
# page's prose), the universal prerender that writes canonical/og/title
# server-side (2.2/2.3 — which is why templates/index.html no longer carries a
# canonical shim), and the corrected AI-crawler taxonomy (2.3.2/2.3.3).
#
# 2.3.4 was the previous network floor (`resolve_site_title` — the /llms.txt
# H1 and the llms viewer's brand chip read SITE_BRAND instead of a fallback).
#
# 2.5.1 is the 402-instrumentation floor (network 1.3.x sync). It adds
# `configure_access` / `configure_viewer_identity` — the hooks lib/access.py
# hands the page-tier policy to — and the tiered corpus documents
# (/llms-small.txt, /llms-full.txt) that LLMS_SMALL_TIER / LLMS_FULL_TIER
# govern. Below it the tier wiring in run.py is dead code and nothing says so;
# run.py enforces this same floor at boot for exactly that reason.
#
# 2.8.0 is the floor; see the block above this line for what it buys.
#
# 2.7.1 remains beneath it. It bought the machine lane's addressing layer — the
# llms.txt v2 discovery relations (rel=alternate / describedby, with matching
# Link headers), the text/plain Accept ramp and the representation digest —
# on top of 2.7.0, which dedups what the prerender injects: below 2.7.0 every
# page serves crawlers a DUPLICATE H1 (the injected header plus the document's
# own) and the home footer doubles its /llms.txt link. 2.7.0 also hardens the
# idempotency probe so a page that merely MENTIONS the prerender marker keeps
# its prerender.
#
# 2.6.1 remains beneath it. Two reasons, and the second is why this line is a FLOOR
# rather than a comment:
#
# 2.6.1 makes the universal prerender VISIBLE to non-JS consumers. At 2.6.0 and
# below the injected block carries a literal `hidden` attribute, so every
# visibility-respecting reader — html-to-text extractors, and arguably crawler
# content-weighting — saw "Loading..." and nothing else, while the prose sat
# right there in the markup. An outside audit read six hosts that way on
# 2026-08-22. JS browsers are unaffected either way: React's mount wipes the
# block, so the fix costs humans nothing.
#
# And the version had to be WRITTEN here, not merely permitted. `>=2.6.0` let
# the resolver pick 2.6.1 in principle, but Docker caches the dependency layer
# on this file's contents: a deploy that changes only application code is a
# cache hit, pip never re-resolves, and the image keeps whatever it first
# installed. Measured live on 2026-08-22 — the deploy that was supposed to
# "pick up 2.6.1" served 2.6.0's hidden div. Editing this line is what
# invalidates the layer, so the floor and the delivery mechanism are the same
# act.
#
# 2.6.0 remains the gate-wave floor beneath it. It ends the invented sitemap
# date: `lastmod=`
# on register_page_metadata is emitted VERBATIM and omitted when absent, where
# 2.5.x swallowed it into **kwargs and kept stamping build dates on every URL.
# It also adds icon autodiscovery (this site still declares configure_seo(
# icons=[...]) explicitly — declared wins, and tests/test_seo_icons.py pins
# that the two sets agree) and the JSON-LD publisher logo.
# 2.8.0 floor (the ledger round, 2026-08-29) — WHY 2.8: (1) ONE
# CLASSIFIER: `classify()` is public and it is the same registry
# robots.txt is rendered from; lib/analytics_tracker delegates to it and
# carries no User-Agent list of its own any more (its list filed ClaudeBot
# as "search" — it is Anthropic's TRAINING crawler — and counted every
# UA-less or library client as a person). (2) THE READ EVENT:
# `on_document_read` hands the app one row per corpus document served —
# tier, lane, vendor, verified, policy, verdict, status, bytes — which
# run.py registers into the tracker's `reads` table. (3) `Vary: User-Agent`
# on the lane-split responses. (4) VERIFIED IDENTITY: vendors with
# published IP ranges are checked against them (`verified`/`unverified`;
# `n/a` where none are published — Anthropic publishes none, so ClaudeBot
# is always n/a). 2.8.1 (policy on every event) is NOT waited on: `policy`
# is None until then and the rollup groups it as "default".
# run.py's `_DIMLL_FLOOR` encodes the same number — grep it, don't move
# one. And the CACHE TRAP: this line changing IS the Docker cache bust; a
# `>=` floor can never pull a new release through a cache hit.
dash-improve-my-llms[flask]>=2.8.0
python-dotenv>=1.0
pydantic>=2.0
